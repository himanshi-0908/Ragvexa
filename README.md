# 🌿 Ragvexa — RAG Engineering & Evaluation Platform

> **Universal RAG. Any Source. Real Answers.**

Ragvexa is a multi-pipeline **Retrieval-Augmented Generation (RAG) engineering and evaluation platform** that goes beyond a generic chatbot. It lets you:

1. **Ingest** documents (PDF, TXT) and web URLs into a personal vector index
2. **Chat** with your data using a configurable retrieval strategy
3. **Benchmark** four retrieval pipelines head-to-head with real metrics

## Retrieval Strategies

| Pipeline | Description | Strengths | Weaknesses |
|---|---|---|---|
| **Naive Dense** | Chroma cosine similarity on NVIDIA embeddings | Fast, simple, semantic | Misses keyword-only matches |
| **Hybrid + RRF** | Dense + BM25 fused with Reciprocal Rank Fusion (k_rrf=60) | Best of both worlds | Higher latency |
| **Hybrid + Reranker** | Hybrid/RRF candidates → cosine reranker sorts final top-k | Highest relevance precision | Requires embedding call for reranking |
| **Query Rewriting** | LLM rewrites the query → Naive retrieval | Better semantic coverage | LLM call adds latency |

### Reciprocal Rank Fusion (RRF)

RRF merges ranked lists without score calibration:

```
score(d) = Σ  1 / (k_rrf + rank_i(d))
           i
```

where `k_rrf = 60` is a smoothing constant that controls the influence of low-ranked documents.

## Evaluation Metrics

### Retrieval Metrics (require ground-truth chunk IDs)

| Metric | Formula | Interpretation |
|---|---|---|
| **Recall@K** | `|relevant ∩ retrieved[:K]| / |relevant|` | How many relevant chunks were found |
| **Precision@K** | `|relevant ∩ retrieved[:K]| / K` | Fraction of retrieved that are relevant |
| **MRR** | `1 / rank_of_first_relevant` | How highly ranked is the first relevant result |
| **nDCG@K** | DCG / ideal DCG (binary relevance) | Reward for highly-ranked relevant results |

### Generation Metrics (LLM-as-a-judge, optional)

| Metric | Measures | Score |
|---|---|---|
| **Context Relevance** | Is the retrieved context on-topic to the query? | 0.0–1.0 |
| **Answer Faithfulness** | Is the answer grounded in context (no hallucination)? | 0.0–1.0 |
| **Answer Relevance** | Does the answer directly address the query? | 0.0–1.0 |

> ⚠️ **Limitations of Synthetic Evaluation**: The evaluation dataset is generated by the same LLM used for generation. Metrics indicate *relative* pipeline differences — not absolute accuracy against a human-labeled gold standard.

## Setup

### 1. Clone and install

```bash
git clone <your-repo>
cd ragvexa_fixed
pip install -r requirements.txt
```

### 2. Configure environment

```bash
cp .env.example .env
# Fill in:
# NVIDIA_API_KEY=...
# DATABASE_URL=sqlite:///./copilot.db
# CHROMA_DB_DIR=./chroma_db
# COOKIE_NAME=ragvexa_session
# COOKIE_SECRET=<random-secret>
```

### 3. Run

```bash
streamlit run streamlit_app.py
```

## Usage — Benchmark Workflow

1. **Ingest** a document → check "Generate eval dataset after ingest"
   - Ragvexa calls the LLM to generate 2 questions per chunk (up to 30 chunks)
   - Query→chunk_id pairs are persisted to SQLite
2. **Go to 📊 RAG Benchmark tab**
3. **Configure**: set K, select pipelines, optionally enable LLM-judge metrics
4. **Run Benchmark** — results include:
   - Summary metrics table (Recall@K, Precision@K, MRR, nDCG@K per pipeline)
   - Bar charts (Recall, MRR, Latency)
   - Failure analysis (queries with zero recall across all pipelines)
   - Query Inspector (per-chunk rank, score, relevance label)
